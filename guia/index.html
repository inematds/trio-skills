Em resumo

O trio-skills junta num só lugar os três pacotes de skills mais usados para agentes de programação: o do Addy Osmani, o do Matt Pocock e o pstack da Lauren Tan. Uma skill é um arquivo de instruções que ensina o agente (Claude Code, Codex, Cursor) a trabalhar de um jeito. O projeto serve para quem programa com agentes e quer usar essas skills sem instalar tudo de uma vez. Ele cataloga as 97 skills por etapa do trabalho, mostra quais têm o mesmo nome e instala um perfil leve, médio ou pesado. Para usar, basta Git e Python 3.

Anatomia

Como uma skill funciona por dentro

Uma skill é uma pasta com um arquivo SKILL.md. O cabeçalho decide quando ela entra.

📇 name + description

É tudo o que o agente lê de cada skill instalada. A descrição é o gatilho: “Use when…”. O corpo só carrega quando a skill é acionada.

🔒 disable-model-invocation

Com true, a skill só roda quando você chama. O agente nunca aciona sozinho. O grill-me e o poteto-mode usam essa trava.

🔗 Skill chama skill

O corpo do grill-me tem uma linha: chamar a skill grilling. Por isso o perfil leve instala as duas.

# pacotes/pocock-skills/skills/productivity/grill-me/SKILL.md
---
name: grill-me
description: A relentless interview to sharpen a plan or design.
disable-model-invocation: true
---
Call the Skill tool with "grilling".

📦 pstack

Plugin do Cursor. /poteto-mode lê o pedido e escolhe o roteiro; /setup-pstack define qual modelo faz cada papel. Fora do Cursor, só por adaptações da comunidade.

/add-plugin pstack   # no Cursor

O fluxo spec → plan → build do Addy

/spec → SPEC.md→ /plan → tarefas com critério→ teste que falha→ código mínimo→ suíte + build→ commit

O /build auto faz todas as tarefas em sequência, mas só aceita o SPEC.md na raiz, em docs/ ou em spec/. Sem ele, para e manda rodar /spec: não inventa requisito.

Guia de uso · passo a passo

Do clone ao perfil instalado

Seis passos. Rode o --dry-run sempre antes de instalar.

1

Clone o projeto

Os três pacotes já vêm dentro de pacotes/, com a versão fixa e a licença.

git clone https://github.com/inematds/trio-skills && cd trio-skills
cat pacotes/*/FONTE.md   # origem, commit e licença de cada um
2

Gere o catálogo

Lê o cabeçalho de cada SKILL.md e organiza as 97 skills por etapa: definir, planejar, construir, verificar, revisar, publicar, depurar, princípios e rotina.

python3 scripts/catalogo.py
# catálogo: 97 skills ({'addy': 25, 'pocock': 38, 'pstack': 34}) → catalogo/CATALOGO.md e catalogo/catalogo.json
3

Veja os conflitos de nome

Mesmo nome em duas skills: o agente usa uma e você não sabe qual. Com --instaladas, ele compara também com as suas pastas de skills e com os plugins instalados no Claude Code.

python3 scripts/conflitos.py               # entre os 3 pacotes: tdd (pocock × pstack)
python3 scripts/conflitos.py --instaladas   # pacotes × sua máquina
4

Escolha o perfil pelo risco

leve (ajuste, tela, protótipo): grill-me + grilling + tdd. medio (recurso novo): + spec, planejamento, implementação incremental, TDD e revisão do Addy, com os comandos /spec /plan /build /review. pesado (produção, segurança, irreversível): as 25 do Addy, 9 comandos e 4 revisores. A lista de cada um está em perfis/.

cat perfis/medio.txt
5

Simule e instale

--destino é a pasta de skills do agente: ./.claude/skills vale só para o projeto; ~/.claude/skills, para todos. O instalador não sobrescreve o que você já tem (só com --forcar).

scripts/instalar.sh --perfil medio --destino ./.claude/skills --dry-run   # mostra o plano, não escreve
scripts/instalar.sh --perfil medio --destino ./.claude/skills
# instalados 12, pulados 0. Reinicie o agente para ele ler as skills novas.
6

Mantenha atualizado e testado

O atualizar.sh copia de novo dos originais (sem .git e .github) e regrava o catálogo. Os testes rodam numa pasta temporária.

scripts/atualizar.sh --conferir   # há versão nova nos originais?
scripts/atualizar.sh
bash tests/run.sh                 # 18 verificações → OK
Exemplos

O que o instalador resolve

Três detalhes que quebram quem instala na mão.

📎 Checklists do Addy

As skills dele apontam para ../../references/. Instalar uma skill avulsa perde essa pasta (o README dele avisa). Aqui ela vai para <destino>/../references e o caminho resolve.

✂️ Comandos fora do plugin

Os comandos do Addy chamam agent-skills:<skill>, nome que só existe dentro do plugin. Copiados como arquivos soltos, o prefixo sai.

👯 Nomes repetidos

Numa máquina real: o plugin context-mode já traz grill-me e tdd; o superpowers traz test-driven-development, o mesmo nome do Addy.

$ python3 scripts/conflitos.py --instaladas   (trecho)
tdd  ← nos pacotes
  - pocock: pacotes/pocock-skills/skills/engineering/tdd
  - pstack: pacotes/pstack/skills/tdd
  - instalada: ~/.claude/plugins/cache/context-mode/.../skills/tdd

test-driven-development
  - addy: pacotes/addy-agent-skills/skills/test-driven-development
  - instalada: ~/.claude/plugins/cache/claude-plugins-official/superpowers/.../skills/test-driven-development
