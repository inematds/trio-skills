En resumen

trio-skills reúne en un solo lugar los tres paquetes de skills más usados para agentes de programación: el de Addy Osmani, el de Matt Pocock y el pstack de Lauren Tan. Una skill es un archivo de instrucciones que enseña al agente (Claude Code, Codex, Cursor) a trabajar de cierta manera. El proyecto sirve para quien programa con agentes y quiere usar esas skills sin instalar todo de una vez. Cataloga las 97 skills por etapa del trabajo, muestra cuáles tienen el mismo nombre e instala un perfil leve (ligero), medio o pesado. Para usarlo, basta con Git y Python 3.

Anatomía

Cómo funciona una skill por dentro

Una skill es una carpeta con un archivo SKILL.md. El encabezado decide cuándo entra.

📇 name + description

Es todo lo que el agente lee de cada skill instalada. La descripción es el disparador: “Use when…”. El cuerpo solo se carga cuando la skill se activa.

🔒 disable-model-invocation

Con true, la skill solo se ejecuta cuando tú la llamas. El agente nunca la activa por su cuenta. grill-me y poteto-mode usan este bloqueo.

🔗 Una skill llama a otra skill

El cuerpo de grill-me tiene una línea: llamar a la skill grilling. Por eso el perfil leve instala las dos.

# pacotes/pocock-skills/skills/productivity/grill-me/SKILL.md
---
name: grill-me
description: A relentless interview to sharpen a plan or design.
disable-model-invocation: true
---
Call the Skill tool with "grilling".
Los 3 paquetes

Qué hay en cada carpeta y cómo se instala cada uno en el original

Todo copiado sin alteración, con la licencia MIT y el commit de origen en pacotes/*/FONTE.md.

📦 Addy Osmani

skills/ 25 · commands/ 9 (spec, planning, build, test, review, ship…) · agents/ 4 revisores · references/ checklists compartidos.

npx skills add addyosmani/agent-skills
# o, en Claude Code:
/plugin marketplace add addyosmani/agent-skills
/plugin install agent-skills@addy-agent-skills

📦 Matt Pocock

38 skills en engineering/, productivity/, misc/ e in-progress/ (en construcción). Plugin que se actualiza solo o copia mediante skills.sh. Nunca los dos: cada skill queda duplicada.

claude plugin install mattpocock-skills@claude-plugins-official

📦 pstack

Plugin de Cursor. /poteto-mode lee el pedido y elige el guion; /setup-pstack define qué modelo cumple cada rol. Fuera de Cursor, solo mediante adaptaciones de la comunidad.

/add-plugin pstack   # en Cursor

El flujo spec → plan → build de Addy

/spec → SPEC.md→ /plan → tareas con criterio→ prueba que falla→ código mínimo→ suite + build→ commit

/build auto hace todas las tareas en secuencia, pero solo acepta el SPEC.md en la raíz, en docs/ o en spec/. Sin él, se detiene y te manda ejecutar /spec: no inventa requisitos.

Guía de uso · paso a paso

Del clon al perfil instalado

Seis pasos. Ejecuta siempre --dry-run antes de instalar.

1

Clona el proyecto

Los tres paquetes ya vienen dentro de pacotes/, con la versión fija y la licencia.

git clone https://github.com/inematds/trio-skills && cd trio-skills
cat pacotes/*/FONTE.md   # origen, commit y licencia de cada uno
2

Genera el catálogo

Lee el encabezado de cada SKILL.md y organiza las 97 skills por etapa: definir, planificar, construir, verificar, revisar, publicar, depurar, principios y rutina.

python3 scripts/catalogo.py
# catálogo: 97 skills ({'addy': 25, 'pocock': 38, 'pstack': 34}) → catalogo/CATALOGO.md e catalogo/catalogo.json
3

Revisa los conflictos de nombre

Mismo nombre en dos skills: el agente usa una y tú no sabes cuál. Con --instaladas, compara también con tus carpetas de skills y con los plugins instalados en Claude Code.

python3 scripts/conflitos.py               # entre los 3 paquetes: tdd (pocock × pstack)
python3 scripts/conflitos.py --instaladas   # paquetes × tu máquina
4

Elige el perfil según el riesgo

leve (ligero; ajuste, pantalla, prototipo): grill-me + grilling + tdd. medio (recurso nuevo): + spec, planificación, implementación incremental, TDD y revisión de Addy, con los comandos /spec /plan /build /review. pesado (producción, seguridad, irreversible): las 25 de Addy, 9 comandos y 4 revisores. La lista de cada uno está en perfis/.

cat perfis/medio.txt
5

Simula e instala

--destino es la carpeta de skills del agente: ./.claude/skills vale solo para el proyecto; ~/.claude/skills, para todos. El instalador no sobrescribe lo que ya tienes (solo con --forcar).

scripts/instalar.sh --perfil medio --destino ./.claude/skills --dry-run   # muestra el plan, no escribe
scripts/instalar.sh --perfil medio --destino ./.claude/skills
# instalados 12, pulados 0. Reinicie o agente para ele ler as skills novas.
6

Mantenlo actualizado y probado

atualizar.sh vuelve a copiar de los originales (sin .git ni .github) y regraba el catálogo. Las pruebas se ejecutan en una carpeta temporal.

scripts/atualizar.sh --conferir   # ¿hay versión nueva en los originales?
scripts/atualizar.sh
bash tests/run.sh                 # 18 verificaciones → OK
Ejemplos

Qué resuelve el instalador

Tres detalles que rompen a quien instala a mano.

📎 Checklists de Addy

Sus skills apuntan a ../../references/. Instalar una skill suelta pierde esa carpeta (su README lo advierte). Aquí va a <destino>/../references y la ruta se resuelve.

✂️ Comandos fuera del plugin

Los comandos de Addy llaman a agent-skills:<skill>, un nombre que solo existe dentro del plugin. Al copiarlos como archivos sueltos, se quita el prefijo.

👯 Nombres repetidos

En una máquina real: el plugin context-mode ya trae grill-me y tdd; superpowers trae test-driven-development, el mismo nombre que Addy.

$ python3 scripts/conflitos.py --instaladas   (extracto)
tdd  ← nos pacotes
  - pocock: pacotes/pocock-skills/skills/engineering/tdd
  - pstack: pacotes/pstack/skills/tdd
  - instalada: ~/.claude/plugins/cache/context-mode/.../skills/tdd

test-driven-development
  - addy: pacotes/addy-agent-skills/skills/test-driven-development
  - instalada: ~/.claude/plugins/cache/claude-plugins-official/superpowers/.../skills/test-driven-development
